# MasterLens 3.0.0

听吧，四种比较，一条基线。

3.0 把 2.7 挂账的四项监听能力补齐。正式版相对 `3.0.0-rc.1` 只做两件事：把三处一眼就能看出来的读数对齐修好，把「必须先播过那一段 / 必须有 ffmpeg」写进界面和文档。

## 四项监听能力

- **频段独听**：频谱页「频段热力」的 10 段、低 / 中 / 高三段都可单击独听；4 阶 Butterworth（24 dB/oct），不做等响补偿，`Esc` 停止。独听只改监听输出，默认旁路不变。
- **选区等响**：时间页拖选后点「选区等响」。工程侧按 BS.1770-4 门限积分（−70 LUFS 绝对门、−10 LU 相对门）测选区，参考侧只解码 `OFS + 选区` 对应段，然后把差值写进当前槽位的 GAIN。工程声音不动，A/B 在等响下比较音色。
- **长文件流式播放**：独立版文件传输改成固定环形缓冲（约 8 MB / 4 s × 192 kHz），读取线程预读 3 s，音频线程只读原子下标；欠载输出静音并显示「缓冲中」，不再把整首歌读进内存，也不会阻塞音频回调。
- **编码 A/B**：文件 QC 用本机 ffmpeg 生成 AAC 256k / MP3 320k，解码回 float WAV 后在同一时间码切换 A 原始 / B 编码后；显示 ΔLUFS / ΔTP / 包体大小。缺少 ffmpeg 或超时会明确失败，不伪造结果。

## 正式版修掉的排版问题

rc.1 的截图里能一眼看出三处错位，这一版都改了：

1. **侧栏读数**（综合响度 / 真峰值 / 响度范围 / 峰响比 / 平台最大衰减）：数字和单位原先各自在一个 24 px 的框里垂直居中，26 px 的主读数会把基线顶高，14 px 的单位再被 `+8 px` 硬推下去。现在两者共用一条基线（`theme::text::drawValueUnit`），行高改由字体自身的 ascent + descent 决定，谁的字号变了都不会再错位。
2. **频谱页读数条**：同一处逻辑，单位原来被 `+16 px` 硬推，主读数越大偏得越多。
3. **设置页页脚**：logo + BERRYSTUDIO 的锁定组合把字标画在顶部 14 px 的条带里，比右边的「开发者 KNGTNPT 兰」和「关闭」按钮高约 7 px。现在字标占满整行高度，与旁边两行文字、按钮共用同一条水平中线。

三处都在浅色 / 深色、80%–200% 每个缩放档下复验；`scripts/check_ui.py` 的 35 个布局场景全部通过，并且已经接进 CI，不再靠人工点。

## 两条使用前提

- **选区等响要先播过那一段**。选区的响度来自时间线已经采到的 100 ms 读数，没播过的区段没有数据，界面会提示「请先播放该段」。它不是整首歌的离线测量——要离线测整首歌，用文件 QC。
- **编码 A/B 要有本机 ffmpeg**。找不到时按钮明确显示不可用。macOS 用 `brew install ffmpeg`；Windows 用 `winget install ffmpeg` 或官网包。

这两条现在同时写在 README、关于页和设置页的说明里。

## 范围与限制

「选区」指 MasterLens 时间线拖选，不是宿主 loop（VST3/AU 没有通用 API）；长选区的循环交给宿主，≤ 10 s 可用 12 s 历史环试听。参考轨仍整段解码，超过 1 小时或 512 MB 会明确拒绝。macOS 继续 ad-hoc 签名、未公证；Windows ARM64 仍为交叉构建，未在 Windows on ARM 实机验证。详细验证见 `docs/performance-3.0.0.md`。
